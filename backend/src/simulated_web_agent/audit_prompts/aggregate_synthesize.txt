Rules:
- REGUŁA JĘZYKOWA (obowiązkowa): NIGDY nie podawaj częstotliwości jako procentu „użytkowników" (np. „72% użytkowników porzuci koszyk"). Odnoś się do „symulowanych person" lub „przebiegów"; traktuj częstotliwości jako hipotezy syntetyczne, nie statystykę populacyjną.
- executive_summary: 3–5 sentences covering the overall picture.
- executive_summary i pozostałe teksty o ukończeniu zadania: liczby i słowa muszą
  zgadzać się z TASK COMPLETION powyżej. „Częściowo" to nie „nie udało się", a
  „porażka" to nie „częściowo". Jeśli ukończenie jest DEKLAROWANE, napisz, że to
  deklaracja, a nie pomiar. Nie przypisuj nieukończenia konkretnej wadzie (np. „co
  uniemożliwiło uczestnikom…"), chyba że problem z `top_issues` / `heuristic_summary`
  opisuje dokładnie ten etap. Słów „krytyczny", „blokuje", „uniemożliwia" używaj tylko
  dla problemów, które umieszczasz w `critical_issues`.
- overall_ux_score: WPISZ DOKŁADNIE {computed_score}. Ocena NIE jest Twoją decyzją —
  została obliczona z dowodów według jawnych reguł (patrz „OCENA OBLICZONA" niżej)
  i zostanie nadpisana, jeśli podasz inną.
- score_rationale: wyjaśnij TĘ ocenę, odwołując się do pozycji z rozbicia poniżej
  — od największego odliczenia. Nie wprowadzaj innych przyczyn niż te, które są
  w rozbiciu, i nie podawaj innych liczb. Możesz krótko wspomnieć, co nie zostało
  wliczone i dlaczego.

OCENA OBLICZONA (wiążąca, z rozbiciem):
{score_breakdown}
- key_strengths: 2–4 items. Only include genuine strengths backed by data.
- critical_issues / serious_issues / minor_issues: only include issues present in the data. Use empty arrays if none.
- priority_recommendations: ranked 1–N, most impactful first. Maximum 5.
- ALL text values must be in Polish.
- Do not invent issues not present in the provided statistics.
- Every issue's heuristic_id MUST correspond to a heuristic present in the heuristic_summary input. Issues about heuristics absent from the input data will be discarded as unverifiable.
